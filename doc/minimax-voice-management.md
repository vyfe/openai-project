# MiniMax 音色管理

入口：管理员登录后访问 `http://localhost:3000/studio/voice`，或从聊天页右上角用户菜单进入“声音工作台 → 音色与语音”。声音工作台是独立功能页（`/studio`，外壳 `views/studio/StudioLayout.vue`），与量化工作台同级，不嵌在管理后台页签里。沿用现有 Vue、Flask 和管理员鉴权，不需要另起服务。本页只做通用语音生成能力，界面文案不绑定具体作品或栏目。

## 配置

向后端**实际加载的配置文件**追加以下段落，填入自己的密钥后重启后端。开发启动脚本使用 `cyf/project/server/conf/conf.dev.ini`；默认/生产使用 `conf/conf.ini`。页面“连接配置”会显示实际配置文件路径。独立占位配置为 [`minimax.ini.example`](../cyf/project/server/conf/minimax.ini.example)，完整模板在 `cyf/project/server/conf/conf.ini.tpl`。

```ini
[minimax]
api_key=<填入你的 MiniMax API Key>
region=cn
key_kind=token_plan
model=speech-2.8-hd
timeout_seconds=180
storage_dir=voice_data
```

支持环境变量 `MINIMAX_API_KEY`，优先于配置文件。`region` 为 `cn` 或 `intl`，必须与密钥站点一致；`key_kind` 可填写 `token_plan`、`m_plan` 或 `pay_as_you_go`，仅标记来源，不改变请求端点或权益。不复用聊天 API 密钥，也不自动回退到其他付费凭据。

### 两套凭据的分工

Token Plan 密钥只能"选择音色生成文本"（T2A 合成），**不能创建音色**（复刻）。因此复刻链路单独用一套计费凭据：

| 链路 | 用哪把密钥 | 说明 |
| --- | --- | --- |
| 音色复刻（`/v1/voice_clone`）、音色列表查询（`/v1/get_voice`）、删除音色 | `[minimax_music].api_key` | 官方 `/v1/get_voice` 返回的是**当前账号**下的音色，因此查询和复刻必须同源，否则复刻出来的音色在列表里对不上 |
| 语音合成（`/v1/t2a_v2`） | `[minimax].api_key` | Token Plan 即可，无需动用计费额度 |
| 音乐生成 | `[minimax_music].api_key` | 同一把计费凭据 |

`[minimax_music]` 段留空时，复刻回退到 `[minimax]` 的语音密钥（单密钥部署保持原行为）。环境变量 `MINIMAX_MUSIC_API_KEY` 优先于配置文件。

> **前提**：复刻出来的音色要在合成时可用，合成凭据所属账号必须能看到该音色。两把密钥属于同一账号时天然满足；属于不同账号时，合成会返回官方错误（音色不可见），此时应让复刻与合成使用同一账号的密钥。
>
> 实测（2026-10-22，开发环境两把密钥分别调用 `/v1/get_voice`）：返回的音色列表完全一致，说明两把密钥属于**同一账号**，计费密钥复刻出的音色可以由 Token Plan 密钥正常合成。换账号时务必重新确认这一点。

### 音色费用与 1008

复刻音色**首次使用**时官方会一次性收取一笔「音色费用」（响应里的 `usage_voice_count` 为 1），这笔钱**只走账户余额**，不走订阅额度：

- 实测：Token Plan 密钥首次合成复刻音色 → `1008 insufficient balance`（订阅额度不覆盖音色费用，账户余额为 0）。
- 同一音色改用计费密钥合成 → 成功，`usage_voice_count=1`（音色费用已付）。
- 之后再用 Token Plan 密钥合成同一音色 → 成功，`usage_voice_count` 为空（音色费用不重复收取）。

程序据此自动分流：台账里**尚未激活**的自定义音色（复刻后为「待首次合成」）首次合成用**计费凭据**；已激活的音色和系统音色用**合成凭据**。若合成凭据返回 `1008`，会换计费凭据重试一次——1008 是明确失败（未产生音频、未计费），重试不会重复扣费。

音色台账、朗读记录和本地 MP3 都按**复刻凭据**的指纹分组（`voice_data/<凭据指纹>/`），因此换复刻凭据后旧记录不可见；切回原凭据可恢复。

官方当前区分 Token Plan 老用户与 M Plan；M Plan 文档列出音频能力，旧 Token Plan 保持原权益。请用页面“检测连接并同步”检查实际密钥对音色查询的权限；查询通过不代表已取得音色复刻权限或合成额度。复刻接口要求账户完成个人或企业认证。此功能按官方 API 返回权限和计费结果工作，不预判某个订阅密钥一定可用。

## 使用

1. **连接配置**：点击”检测连接并同步”，获取当前账号可用音色；错误会显示官方业务码和处理建议。检测只查询音色，不生成语音，用的是复刻凭据（`[minimax_music]`）。页面会分别标注复刻凭据和合成凭据的来源与就绪状态。
2. **复刻我的音色**：上传本人或已授权录音，MP3/M4A/WAV，10 秒–5 分钟、最大 20 MB；建议 1–2 分钟安静单人朗读。可选上传短于 8 秒的示例及对应文本。点击“上传并复刻音色”后录音会传至 MiniMax，原始录音不在后端落盘。
3. **首次朗读**：复刻成功后自动进入语音合成，可用短文试听。这里调用正式 T2A，可能产生首次音色费用和语音费用。须在复刻后 **7 天内**正式调用；未激活音色不会由云端列表接口返回，因此页面保留本地“待首次合成”记录。超时后保留“创建结果待确认”记录，不自动重试。
4. **音色库**：支持自定义/系统筛选、搜索、本地改名、设为默认和删除云端自定义音色。删除需输入完整 ID；系统音色不能删除。音色 ID 不可改名，本地显示名称不写回 MiniMax。页面顶部是**音色保活**面板，卡片上会显示每个音色的保活剩余天数。
5. **语音合成**：粘贴已有正文或导入 TXT/Markdown，选择音色、模型、语速/音量/音调/情绪，点击“提交生成并保存”。先将正文与参数写入现有 SQLite，再请求生成音频；成功后保存云端音频链接、过期时间、实际时长、计费字符数并下载本地 MP3。3–4 分钟目标用于验收，不自动反复合成或改写正文。合成上限为 9999 字符。
6. **合成记录**：播放、下载 MP3 与对应正文，复制音频链接，或载入历史正文编辑后提交。MiniMax 返回的音频链接有效期为 **24 小时**，本地 MP3 保留后可继续播放；如备份下载失败，链接与正文仍在 SQLite 中，播放或下载会在链接有效期内重试下载，不会重新合成。所有文件下载走管理员鉴权，浏览器用 Blob 播放，不在音频链接中放入令牌或 MiniMax 密钥。
7. **导出默认音色配置**：设置默认音色后导出 `minimax-voice-profile.json`，包含 provider、region、voice_id 和默认朗读参数，不含密钥。

## 音色保活（7 天不调用会被删除）

复刻出来的音色如果 7 天内没有正式调用，会被 MiniMax 删除。音色库页顶部的**保活面板**提供：

- **每日自动激活到期音色**开关：默认开启。
- **每天执行时间**（时/分，默认 03:17，避开整点）。
- **立即执行一次**：不等定时器，马上检查并补激活。
- 每个音色卡片显示"保活还剩 N 天"，到期前一天会标红。

服务端行为：

- 到期判定 = `最后一次正式调用时间 + 7 天`，提前 1 天（即剩余 ≤ 1 天）进入待保活队列；没有调用记录时用创建时间兜底。系统音色不参与保活。
- 保活覆盖**所有自定义音色**：本地复刻的和从云端"同步"来的都会登记进台账（同步时把云端 `voice_cloning` / `voice_generation` 音色也写入本地台账），否则在别处复刻的音色 7 天后仍会被官方删除。
- 激活方式：用该音色合成一句日期播报（"现在是 2026 年 10 月 22 日 20 时 45 分。"），只生成云端链接，**不保存本地 MP3**，也不写入合成记录，避免污染产出列表。
- 保活调用使用**音色所属账号的凭据**（`clone_client`），确保一定调得到该音色；日常手动合成仍走合成凭据。
- 每次保活都会刷新音色的"最后激活时间"，并累计保活次数；失败的保活会把官方错误记到台账的 `last_keepalive_error`，页面在"立即执行"后提示。
- 定时器在后端启动时拉起（`service/minimax_keepalive.py`），每天在设定时间执行一次；多进程部署时每个进程都会执行，靠文件锁避免重复激活。
- 保活会消耗少量额度（一句日期播报），可在面板上随时关闭或对单个音色禁用（`disabled_voices`）。

## 本地数据与请求行为

正文编辑器支持“粘贴剪贴板”和“复制正文”；浏览器未开放剪贴板权限时，可在正文框中使用系统复制、粘贴快捷键。音色接口只记录访问元数据，不在请求日志中记录录音、正文或临时链接。

复用平台现有 SQLite（配置项 `[log].sqlite3_file`），启动时自动创建两张新表，不修改原有表：

- `voice_account_state`：音色台账、显示名称、默认音色、最近同步结果和保活设置（开关、每日时间、禁用列表）。
- `voice_reading`：正文、标题、音色、朗读参数、生成状态、音频 URL、过期时间和用量。列表显示最近 200 条，数据库保留完整记录。

`voice_data/<凭据指纹>/audio/` 保存 MP3；下载正文时从 SQLite 导出 TXT。音乐创作共用同一凭据目录，文件放在 `voice_data/<凭据指纹>/music/`，见 [minimax-music-management.md](./minimax-music-management.md)。更换密钥或区域会隔离数据，切回原凭据可看到原记录。音频目录已加入 `.gitignore`；备份时同时备份平台 SQLite 与该目录。原录音仅在上传请求内存中处理，台账不含密钥。此处暂存的是 MiniMax 返回的临时云端链接，尚未接入自有 OSS 存储桶。

请求前保存 `generating` 记录；明确失败标记 `failed`，超时标记 `unknown` 并保留正文。云端链接返回后立即入库为 `remote_ready`，本地 MP3 下载成功后为 `ready`。服务在生成途中退出时，原 `generating` 记录会保留，需先检查云端结果后再决定是否重新提交。

后台会串行执行同一凭据下的操作，文件锁支持多线程和 Linux/macOS 多进程。云端请求不自动重试；浏览器音色客户端也禁用失败后的认证重放，保留请求前的登录刷新。若超时、网络中断或服务端本地保存失败，先检查云端或本地结果，避免立即再次生成。

启动与停止沿用根目录 `./start-dev.sh`。后端超时默认 180 秒；生产反代如有更短的读取超时，需按实际部署设置，否则页面可能先超时。生产数据目录应持久化且只供后端访问。

## 接口

均在 `/never_guess_my_usage/voice` 下并要求管理员权限：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/state` | 脱敏配置、本地音色与历史 |
| POST | `/sync` | 查询云端全部音色 |
| POST | `/clone` | multipart 录音复刻 |
| POST | `/preference` | 本地别名与默认音色 |
| POST | `/delete` | 删除云端自定义音色 |
| POST | `/synthesize` | 正式 T2A，正文与链接入 SQLite，备份 MP3 |
| GET | `/reading/<id>` | 查询单条记录与原文，供重新载入 |
| GET | `/audio/<id>/<mp3或txt>` | 鉴权下载本地文件 |
| GET | `/profile` | 导出不含密钥的默认音色配置 |
| GET | `/keepalive` | 保活状态：开关、每日时间、各音色剩余天数 |
| POST | `/keepalive` | 保存保活设置 |
| POST | `/keepalive/run` | 立即执行一次保活激活 |
