# 慧聊登录入口与复合角色改造任务书

状态：待开发。基线：`70aa78f`，核对日期：2026-11-08。本文规定开发、测试、回归及发布的完成条件；任务勾选与执行记录由实施者填写。

## 1. 目标与交付范围

保留“慧聊”品牌，将登录页调整为聊天、量化、声音三个功能的统一入口。用户选择目的地后登录，后端根据当前账号授权决定能否进入；新注册账号默认只开通聊天，其余功能由管理员组合授权。

本期交付：

- 登录页、注册表单、未开通功能引导，以及桌面和移动端适配。
- `chat / quant / sound / admin` 角色模型、存量迁移、实时鉴权与资源归属控制。
- 登录、刷新、当前用户、用户管理接口及前端认证状态同步。
- 按权限显示的顶栏切换、模块导航、管理后台用户新增与编辑。
- 自动化测试、人工回归记录、迁移与发布回滚说明。

本期保持现有业务工作台结构；登录后直接进入所选功能。不增加独立的登录后门户，不引入自助开通、审批流、动态角色管理平台、套餐计费或新的登录方式。`admin.css` 中遗留的非 scoped `:deep()` 清理另行处理，本期只回归受影响的后台界面。

## 3. 登录入口与交互规格

### 3.1 页面结构

```text
慧聊                                              语言 / 主题

选择今天要使用的功能                      登录慧聊
┌ 智能对话 · 注册即开通 ┐                 账号
│ 日常问答、写作与思考   │                 密码
└──────────────────────┘                 [登录并进入智能对话]
┌ 量化研究 · 需授权 ────┐                 注册账号
│ 策略、回测与研究报告   │
└──────────────────────┘                 新账号默认开通聊天。
┌ 声音创作 · 需授权 ────┐                 量化与声音需联系管理员开通。
│ 音色、语音与音乐创作   │                 [联系管理员]
└──────────────────────┘                 管理员入口（次级链接）
```

- 三张功能卡单选，整卡可点击；默认聊天。量化、声音在登录前均可选择，“需授权”为说明标签。
- 品牌使用“慧聊”；页面标题为“慧聊 · 智能对话、量化与声音创作”。功能描述保持一行，避免将开发说明放入页面。
- 登录主按钮随选择变化：`登录并进入智能对话 / 量化研究 / 声音创作`。提交中显示忙碌状态并禁止重复提交。
- 管理员入口复用同一登录表单，目标为 `/admin`，不增加第四张主功能卡。
- 联系方式沿用微信 `pata_data_studio`；复用统一的联系信息来源，登录、注册和未授权引导保持一致，提供复制与复制成功反馈。
- 已登录访问 `/login` 时展示功能选择与当前账号，主按钮改为“进入…”，同时提供退出/切换账号；移除固定跳转聊天的逻辑。

### 3.2 视觉与可访问性

- 延续已确认原型的暖色背景、清晰卡片和克制强调色；选中项同时有边框、标记和文字状态。
- 大屏为左功能区、右表单；窄屏改为品牌、功能选择、表单、开通引导的单列顺序。覆盖 1440、1024、768、390、360 px 宽度，页面无水平滚动。
- 使用现有主题 tokens、Element Plus 和图标，沿用应用 `.dark` 主题状态，支持中英文和刷新后的主题恢复。
- 功能选择使用原生 radio 或等效的可访问 radio group，支持方向键；表单有可关联标签、可见焦点、Enter 提交和错误聚焦。复制、主题切换等辅助按钮不提交表单。
- 样式限定在登录组件或 `.login-` 命名空间内；组件内部调整使用 scoped 样式中的 `:deep()`。保留现有暗色 tokens 与 Tailwind dark variant 配置。

### 3.3 注册行为

- 登录页切换到注册表单；保留用户名、密码、确认密码和可选 API Key。API Key 收入“高级设置”，沿用现有限额与默认凭据规则。
- 展示只读初始权限：“聊天已开通”“量化需管理员开通”“声音需管理员开通”。注册者不能勾选额外角色。
- 客户端验证两次密码一致；服务端继续执行用户名、密码和重复账号校验。
- 注册成功后回到登录表单，预填用户名、清空密码、目标设为聊天；保持当前注册后不自动登录的行为。
- 用户自带聊天 API Key 只影响聊天凭据；声音继续使用服务端 MiniMax 配置。

### 3.4 登录状态与目的地规则

| 状态/触发 | 页面及请求行为 |
| --- | --- |
| 账号或密码错误 | 停留表单并显示认证错误，保留用户名与目标 |
| 认证成功且目标已开通 | 更新凭据与角色，再进入目标；深链进入具体子页 |
| 认证成功但目标未开通 | 保留登录态，显示“该功能暂未开通”、当前可用功能入口与联系管理员；由用户点击入口继续 |
| 目标为管理员入口，账号非管理员 | 同样显示权限引导，不能访问管理接口 |
| token 失效/账号停用 | 清理该账号业务状态，回登录并保留合法目的地 |
| 当前页权限被撤销 | 下次请求返回 403，更新角色并进入权限引导；不重放原业务操作 |
| 网络错误/读取当前授权失败 | 显示可重试错误，保留凭据；完成服务端确认后才进入受保护页面 |

目的地解析集中实现：

1. 深链使用 `/login?redirect=<站内路由>`；功能选择使用 `app=chat|quant|sound|admin`。只接受路由表可解析的站内路径，并按最终路由权限校验。
2. 显式功能选择会更新并取代先前深链目的地；最终以用户当前选择为准。
3. 未显式选择时，优先恢复合法深链，其次使用该账号上次仍有权访问的功能；均不存在时，按聊天、量化、声音、管理的顺序选首个可用入口。
4. 拒绝外部 URL、协议相对地址、编码后的外部跳转及未知路径。非法参数回到默认选择，不发起外部跳转。
5. 显式目标未授权时必须展示权限引导；账号切换时清理上一账号的目的地偏好和业务缓存，退出登录清理 token 与角色。

## 4. 角色与页面权限

### 4.1 角色语义

| 存储角色 | 用户标签 | 生效范围 |
| --- | --- | --- |
| `chat` | 聊天用户 | 聊天能力及本人对话数据 |
| `quant` | 量化用户 | 量化业务能力、共享行情只读及本人研究数据 |
| `sound` | 声音用户 | 音色、语音、音乐业务及本人作品 |
| `admin` | 管理员 | 全部业务能力、全部资源及平台管理 |

- 普通账号可以组合三种业务角色，也可仅有量化或声音权限，聊天并非所有账号的强制前置权限。
- 管理员规范化存储为 `["admin"]`，有效权限包含三个业务模块和管理。业务角色不能推导出管理员身份。
- 管理员创建普通账号默认勾选聊天；启用账号至少选择一个角色。未知角色、空角色提交返回 400；异常存量空角色账号按无业务权限处理。
- 停用账号不能登录、刷新或继续访问业务。角色撤回在服务端下一次请求生效；已提交的外部生成任务按原任务处理，不重复发起。

### 4.2 页面与操作矩阵

管理员具备表内全部权限。下表列出普通账号所需权限；同页中的管理操作按操作粒度另行控制。

| 页面/能力 | 普通账号要求 | 边界 |
| --- | --- | --- |
| `/login`、注册、健康检查 | 公开 | 登录后的功能可用性仍读服务端授权 |
| 个人设置、改密、本人浏览器配置、通知 | 已登录 | 不要求聊天角色；保护本人数据 |
| `/chat` 及聊天业务接口 | `chat` | 模型调用、历史、图片、handoff、流式及取消均校验 |
| `/quant/overview`、`/quant/data`、`/quant/industry` | `quant` | 行情只读；个人统计按本人范围聚合 |
| `/quant/strategy`、`/quant/runs`、`/quant/backtest`、`/quant/operations` | `quant` | 本人策略、执行、回测、报告、操作及持仓；允许本人业务写入 |
| `/quant/scheduler`、`/quant/ai-memory`、`/quant/im-positions` | 仅管理员 | 本期保留全局调度、共享 AI 记忆和 IM 配置/运营边界；普通用户持仓复用业务页 |
| 采集、导入、回填、指标重算、全局股票/板块维护 | 仅管理员 | 共享数据写操作，包括目前只要求登录的写接口 |
| Prompt 模板 | `quant` 可读启用的公开业务模板 | 全局增删改及系统模板配置仅管理员 |
| `/studio/voice`、`/studio/music` | `sound` | 个人音色复刻、合成、音乐与翻唱；服务端校验归属 |
| 音色全局同步、云端配置/profile、全局保活设置与手动执行 | 仅管理员 | 普通用户的默认音色偏好只影响本人 |
| `/admin` 及所有管理接口 | 仅管理员 | 含用户授权、SQL、运行配置和全局统计 |
| Agent 认领/上报、Worker、飞书回调 | 专用服务边界 | 见 §5.4；普通业务角色不能调用采集上报或代替回调身份 |

顶栏统一列出当前账号可用的“智能对话、量化研究、声音创作、管理后台”，包含当前模块的选中状态。无权入口不出现在顶栏菜单；登录页始终保留三个功能介绍。清理各工作台固定“返回聊天”的跳转，使用统一功能切换与登录入口。

## 5. 后端实施规格

### 5.1 存储与权限服务

- 平台库新增 `UserRole` / `user_role`：`user_id` 关联 `User.id`，`role` 为白名单角色，唯一约束 `(user_id, role)`，包含创建时间；纳入 `ALL_MODELS`。
- 新增集中权限服务，建议文件 `service/permission_service.py`：规范化角色、有效权限、模块检查、管理员检查和资源归属策略。每请求将认证主体及已读取角色保存在请求上下文。
- `User.role` 保留一个兼容周期，仅投影为 `admin/user`；实际授权只读取 `user_role`。旧字段和 token 中的旧角色均不能恢复已撤销权限。
- 普通账号角色排序固定为 `chat, quant, sound`，管理员仅 `admin`。创建账号、替换角色、更新兼容字段在同一平台库事务内完成。
- roles 只接受已知字符串组成的数组，去重后规范化；包含 admin 时归一为 `["admin"]`。未知值、错误类型或空数组拒绝写入。
- 用户列表批量读取角色，避免每行额外查询；认证复用 token 查找已得到的 User，避免为角色、用户名和状态重复读取同一用户。角色结果只在当前请求内复用。
- 管理员改权记录操作者、目标用户、前后角色与结果，复用平台日志；不记录密码、token、API Key、音频正文或歌词。
- 最后一个启用管理员不能被降权、停用或删除，检查与写入置于同一写事务。账号删除改为保留身份主键的软删除并撤销 token，避免历史资源转移或用户 ID 被复用。

### 5.2 认证与错误协议

- 继续使用现有 access/refresh token，不扩展为 JWT 改造。登录、refresh、`auth/me` 均返回数据库的当前角色快照。
- access/refresh 每次认证均检查账号是否启用；旧 access 继续可用于认证，但其内嵌角色不参与授权。撤权后 refresh 不得恢复旧角色。
- access 过期不能同时清除尚有效的 refresh；有效 refresh 能正常换取新 access。停用、软删除、改密或显式撤销后，原凭据不能恢复会话。
- 本期复合角色基于 `use_db_auth=True`。存量配置账号先按既有用户迁移流程进入平台库；生产不得通过配置凭据分支绕过当前角色与停用检查。
- 模块装饰器和管理员装饰器复用同一认证结果；资源读取/执行还需通过 §5.3 的归属检查。
- 兼容旧用户名/密码调用时，同样执行当前角色及归属检查；请求已显式携带无效 bearer 时返回 401，不切换到请求体中的另一账号身份。
- 401 表示缺失、失效凭据或账号停用；403 表示已认证但缺少模块/操作权限。跨用户私有资源统一返回 404，避免暴露资源存在性；合法角色访问不存在资源同样返回 404。
- 统一 JSON 错误保留 `success:false`、`msg`，补充稳定 `error_type`：`UNAUTHENTICATED / PERMISSION_DENIED / RESOURCE_NOT_FOUND / VALIDATION_ERROR`。权限错误可附 `required_role`，不得附内部路径或其他用户信息。
- SSE 建连前可用对应 HTTP 错误；已开始 SSE 后，错误按现有 SSE `error` 帧和关闭流程返回。前端停止拼接内容并展示错误。
- 单独审计聊天公开目录接口：模型目录、系统 Prompt 和使用量改为相应业务鉴权；登录页仅消费公开品牌与联系信息。通用个人接口保持所有已登录业务账号可用。
- 遗留 `/set_info` 查询入口收紧为管理员；`/download` 虽名为下载，实际为附件上传，需按聊天业务鉴权并核对后续文件访问链路。私有文件不能通过静态目录旁路读取。

### 5.3 数据归属与共享范围

新增归属统一使用稳定的 `User.id`。量化库采用普通整数 `owner_user_id` 引用平台用户；两库之间不声明跨库外键。服务端从认证主体赋值，客户端不能通过 `owner_user_id / username / created_by` 改变身份。

| 资源 | 本期存储及访问约定 |
| --- | --- |
| Instrument、K 线、市场/行业行情与指标等基础数据 | 量化用户共享只读；共享缓存不夹带个人报告或持仓 |
| `QuantStrategy` | 新增可空且有索引的 `owner_user_id`；新数据必须填写当前用户 ID |
| 策略 Run、Signal、Backtest、Report 与投递记录 | 从所属策略/报告继承授权；查询包含父资源约束，创建校验全部关联资源归属，不新增重复 owner 字段 |
| `QuantOperationRecord`、`QuantPositionJournal` | 新增 `owner_user_id`，覆盖无策略的独立记录；关联 strategy/run/signal/operation 必须属于同一用户 |
| 音频朗读 `VoiceReading`、音乐 `MusicTrack` | 新增 `owner_user_id`；保留现有凭据 `scope`、区域、文件锁和备份目录，查询同时约束 scope 与 owner |
| 自定义音色 | 新增 `VoiceAssetOwnership` / `voice_asset_ownership`，唯一 `(scope, voice_id)`，记录 owner；系统音色共享，自定义音色限本人和管理员使用/删除 |
| 翻唱预处理资源 | 预处理记录/凭据绑定当前用户，生成时验证 `cover_feature_id` 属于本人，不能凭他人 ID 创建作品 |
| 默认音色偏好 | 复用本人浏览器配置中的独立字段保存，并校验该音色可用性；普通用户不能写全局 `VoiceAccountState.default_voice_id` |
| 旧数据 owner 为空、未登记的旧自定义音色 | 仅管理员可见和操作；按明确映射认领，迁移不默认分配给所有量化/声音用户 |

落实要求：

- 列表、搜索、统计、分页总数、详情、导出、执行、修改、删除及关联查询使用同一可见范围；先过滤再分页/聚合。
- 有子记录的策略/报告采用保留父资源及归属的归档方式；已归档资源不可再执行，历史子记录继续沿原父资源鉴权。历史孤儿记录只供管理员处理。
- 检查 dashboard、报告预览、持仓汇总、行业报告与共享 AI 记忆是否混入私人内容。普通量化用户只获得共享市场信息与本人内容；共享 AI 记忆及 IM 日志本期保持管理员访问。
- `Voice/Music.snapshot` 对普通用户只返回可用模型、可用音色与本人记录；移除配置路径、存储目录、密钥种类、内部 Host 和全局管理信息。
- 普通声音用户播放/下载通过带认证的接口获取 Blob；响应不透出第三方临时音频链接。记录详情、本地文件及预处理资源同样校验归属；已签发的第三方临时链接按服务商有效期失效。
- 所有个人缓存、生成记录及异步任务携带用户维度；账号切换清理旧缓存。重命名账号不改变新增 owner 关系。
- 两个用户可以独立使用同名策略：将当前全局策略名唯一约束调整为非空 owner 的 `(owner_user_id, name)` 唯一索引，并为空 owner 建立独立的 name 唯一索引，旧系统策略仍保持管理员范围。
- 归属缺失的异常记录默认仅管理员处理；普通用户不能把他人的资源链接到自己的记录。管理员创建业务数据默认归管理员，需要指定归属时也必须校验目标账号及角色。

### 5.4 服务进程与付费调用

- Agent `/quant/client/tasks/{claim,report}` 本期沿用管理员服务账号凭据并收紧为管理员；`client_id` 只用于任务租约匹配，不能替代认证。更新客户端回归及运维说明。
- Worker 保持受控后台执行；执行个人策略/报告任务前读取资源 owner，验证用户启用及量化权限。撤权后的待执行任务标记跳过/取消并记录原因，不能继续产生本人新报告。
- 原有 owner 为空的系统任务仅由管理员配置和服务进程执行。执行链携带真实资源归属，不能信任 payload 中的用户名来放行。
- 飞书签名/挑战验证沿用现有专用通道；账号绑定后的业务动作按当前用户角色及资源归属检查，不能把回调验签成功当作用户授权。
- 保持 MiniMax 请求前刷新、发出后不自动重放的策略，保留同凭据操作锁；401、403、超时、刷新角色和导航均不重新提交付费请求。音频备份失败只重试下载。

### 5.5 接口契约

业务路径均以 `/never_guess_my_usage` 为前缀；沿用已有 JSON 外层协议。

login、refresh、auth/me 共用 `user_id / username / roles / role` 账号快照，token 字段仅由前两者返回。认证快照、私人业务响应及文件使用 `Cache-Control: private, no-store`，避免跨账号缓存。

| 接口 | 本期契约 |
| --- | --- |
| `POST /login` | 请求仍为账号密码；成功返回账号快照和现有 token/过期字段。目的地由前端解析，不参与授权 |
| `POST /token/refresh` | 返回新 token 与当前账号快照；账号停用/删除返回 401 |
| `GET /auth/me`（新增） | 返回账号快照；不得返回密码、API Key 或 token 明文 |
| `POST /register` | 沿用 username/password/api_key；成功只授予 `["chat"]`。携带 role/roles 字段返回 400，不创建越权账号 |
| `GET /user/list`、`GET /user/get/<id>` | 每个用户返回 roles 与兼容 role；角色过滤使用成员关系，筛选 quant 能命中组合角色 |
| `POST /user/create`、`POST /user/update` | 新前端提交 roles 数组，服务端校验白名单和组合后原子替换；保留现有其他字段校验 |
| `POST /user/delete` | 软删除并清除 token，保护最后一个启用管理员；已有资源归属保持原 ID |

登录成功的数据示例（其他 token 字段沿用现有实现）：

```json
{
  "success": true,
  "data": {
    "user_id": 42,
    "username": "researcher",
    "roles": ["chat", "quant"],
    "role": "user",
    "access_token": "<opaque-token>",
    "refresh_token": "<opaque-token>"
  }
}
```

兼容一个发布周期的旧用户管理客户端：新增请求仅有 `role=user/admin` 时分别映射聊天/管理员；更新请求未提供 roles 且兼容 role 未变化时保留原组合角色。明确从 user 升 admin 时设为 `["admin"]`，从 admin 降 user 时设为 `["chat"]`。同时提交 roles 和不一致的兼容 role 返回 400。新前端统一提交 roles，禁止普通资料保存意外清空已有量化/声音权限。

### 5.6 存量迁移

交付平台迁移工具（拟新增 `tools/platform_permissions_migrate.py`）和版本表 `platform_schema_migration`。工具支持 `--db`、`--mode dry-run|soft|hard`、`--output`：dry-run 输出 SQL/计数且不写库，soft 先生成可恢复备份，hard 仅用于可重置开发库。平台库复用 Peewee 迁移能力，量化库继续使用项目指定工具。

1. 在脱敏副本演练：统计旧角色、禁用账号、角色异常、各业务表和音频记录数量；列出 owner 认领映射。未知旧角色阻止应用并报告，不猜测授权。
2. 平台库创建角色/音色归属/迁移版本表，补朗读、音乐 owner 列与索引；量化库补策略、操作、持仓 owner 列和索引，迁移策略名唯一约束。
3. 旧 `role=user` 一次性回填 chat，旧 `role=admin` 回填 admin；禁用账号保留角色但仍禁用。回填与完成标记同事务；重复执行/重启不能补回撤销的权限。
4. 历史业务 owner 默认空；只应用已校验的显式认领映射，校验 ID 存在、同一关系链归属一致及不存在音色冲突。不从 created_by 猜测资源归属。
5. 比较迁移前后数量、唯一约束、索引、凭据 scope 和抽样内容；演练失败回滚与重复执行，保存报告。
6. 生产先停止写入与相关 Worker，使用 SQLite 一致性备份同时保存平台库、量化库及文件/映射清单，再依次迁移。两库不具备共同事务，任一失败保持维护状态，恢复成对备份后重试。

量化字段迁移命令，在 `cyf/project/server/` 执行，路径中的日期按实施日替换：

```bash
.venv/bin/python tools/quant_db_migrate.py --mode dry-run --output ddl/2026-11-08_user_ownership.sql --change-name user_ownership
# 可重置的开发库
.venv/bin/python tools/quant_db_migrate.py --db <开发库绝对路径> --mode hard --change-name user_ownership
# 生产库，完成一致性备份和维护切换后执行
.venv/bin/python tools/quant_db_migrate.py --db <生产库绝对路径> --mode soft --change-name user_ownership
```

该工具自动补列；索引、唯一约束重建、角色回填和资源认领须由版本化迁移显式实现。提交具备字段语义的 DDL 与回滚步骤；不能只依赖 `create_tables(safe=True)` 或吞掉异常的启动补列。启动检查关键迁移版本，缺失时停止业务启动并报告，不在每次启动重新推导授权。

## 6. 前端实施规格

- 新增共享角色类型与功能元数据，建议 `src/auth/permissions.ts`、`src/auth/apps.ts`。同一配置提供角色到入口映射、标签键、图标与默认路由；页面使用 `sound` 对应 `/studio`。
- Pinia 保存 roles 与认证状态，提供 `hasRole / canAccessApp / isAdmin`；移除按单值 role 决策的分散代码。localStorage 仅用于恢复线索，受保护导航前需完成服务端确认。
- 登录、refresh、`auth/me` 统一应用角色快照。应用恢复、跨模块导航、标签页重新激活和收到 403 时同步当前授权；并发同步复用同一个进行中请求，避免组件重复拉取。
- 路由使用统一 `requiredRole` 等元信息；删掉 quant/strategy、backtest、scheduler 等重复硬编码守卫，按 §4.2 区分业务与管理子页。数据请求同样由后端校验。
- 401 沿用现有刷新策略，普通请求至多重试一次；403 不触发 token 刷新重试。刷新/确认角色失败必须显示可恢复错误，不能用本地旧角色直接放行。
- `AppHeader` 展示可用模块及当前模块，聊天包含在同一菜单内；页面品牌、返回入口和退出登录使用统一目的地规则。
- 登录页、注册、授权引导共用联系信息组件/配置；注册权限只读。原型中的模拟账号、测试开关和演示状态管理不进入生产代码。
- `UserTable` 列表显示多个角色标签，支持成员角色筛选；新增/编辑使用三个业务复选框及管理员开关。管理员开启时显示全部业务已生效并禁用业务项，提交 `["admin"]`；关闭管理员时回到聊天默认值，允许重新组合后保存。
- 编辑时正确回显仅 quant、仅 sound 等账号；权限、启用状态和普通资料一起校验提交。停用独立展示，不使用“清空角色”代替停用。
- 普通量化/声音用户不渲染全局运维按钮或配置详情，相关 composable 不预加载管理员接口；业务表格只消费自身可见的数据与分页结果。
- 中英文 key 同步，复用已有主题管理与 HTTP 客户端；不要为登录页另建一套 token 刷新、权限解析或暗色样式体系。

## 10. 发布、回滚与最终验收

### 10.1 发布顺序

1. 完成迁移演练、接口授权清单及测试报告，打出平台库/量化库/音频文件一致性备份；记录旧前后端版本与回退路径。
2. 进入维护窗口，暂停写入和相关Worker；应用迁移，部署支持旧前端契约的新后端。检查迁移版本、角色映射、旧token和现有管理员工作流后恢复受控进程。
3. 在预发布验证全部角色矩阵与A/B隔离。后端权限和owner检查未完成前，不向普通账号授予quant/sound。
4. 构建新前端，按现有EdgeOne流程发布到预览环境再正式发布；确认控制台的正式发布状态及线上入口版本。
5. 执行R02真实跨版本旧页面检查及R03域名链路检查，再用临时业务账号验证开通、切换、撤回和停用。生产使用既有作品与只读数据进行冒烟。
6. 记录实际线上版本、执行结果和遗留非阻断项，更新AGENTS中的认证/路由说明、接口文档及部署手册。

### 10.2 回滚规则

- 前端可回滚到已验证兼容版本，新后端保留roles与兼容role响应；旧前端展示有限，但服务端继续执行新授权边界。
- 后端优先回退到保留新角色和资源校验的兼容版本。必须回到改造前版本时，先阻断普通用户的量化/声音访问并暂停相关任务，再在维护窗口恢复相配套数据与程序；不能单独回退后端而继续开放新业务角色。
- 数据恢复应覆盖同一时间点的两库、认领映射与文件清单；恢复前保存故障现场。记录维护窗口后的新增写入，防止静默覆盖作品和授权变化。
- 新增角色/归属表可在代码回退后保留，禁止直接删列清表作为常规回滚。执行恢复后重新验证管理员、旧token、数据归属与启动状态。
